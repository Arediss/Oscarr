# 0.10.0 validation

Reviewed on 2026-10-25. Release notes: [French and English](0.10.0.md).

## Dependency PRs

The changes from Dependabot PRs #229, #230, #231, #239 and #240 are integrated on the development branch; the PRs themselves are left open. Their original CI and CodeQL runs succeeded. Those runs do not validate the combined release branch.

| Proposal | Integrated version |

| #239: 22 minor/patch updates | Included, with additional compatible security patches listed below |
| #240: undici 8.10.2 | Superseded by undici 8.12.3 |
| #229: docker/build-push-action | 7.3.0, pinned to `53b7df96c91f9c12dcc8a07bcb9ccacbed38856a` |
| #230: actions/upload-artifact | 7.0.0, pinned to `bbbca2ddaa5d8feaa63e36b76fdaad77386f024f` |
| #231: sigstore/cosign-installer | 3.9.1, pinned to `398d4b0eeef1380460a10c8013a76f728fb906ac`; installs cosign 2.5.2 |

The September lockfile still had 18 audit findings when reviewed. Compatible security fixes include fastify 5.12.7, undici 8.12.3, zod 4.6.7, vite 8.3.5, vitest 4.1.12, postcss 8.5.31, concurrently 10.0.6, and their affected transitive dependencies. React/react-dom/types are aligned at 19.3.0.

Nodemailer is deliberately upgraded to 10.2.1 because the maintained fixes are outside v9. Its [v10 breaking change](https://github.com/nodemailer/nodemailer/releases/tag/v10.0.0) requires Node 20+, which the Node 22 image satisfies. The existing SMTP integration tests pass with real local SMTP connections; no production email was sent for testing.

`postcss-selector-parser` is overridden to 7.1.7 to address [the parser advisory](https://github.com/postcss/postcss-selector-parser/blob/master/CHANGELOG.md) without migrating Tailwind 3 to Tailwind 4. CSS compilation and browser checks pass. Revisit the override when Tailwind's supported dependency range includes the patched parser.

Both the workspace lockfile and the separate production-runtime lockfile audit cleanly (zero findings). `npm audit signatures` reports no invalid or missing signatures. Installs were frozen with scripts disabled, followed by rebuilding only the existing Prisma, esbuild and native dependencies. No new install-script dependency was introduced.

## Action compatibility

[build-push-action v7](https://github.com/docker/build-push-action/releases/tag/v7.0.0) requires Actions Runner 2.327.1+ for Node 24. The release workflow uses a self-hosted macOS ARM64 runner, so that minimum must hold there. Existing checkout/setup-node v5 already require the Node 24 runner generation. No removed Docker action environment variables or legacy export-build tool are used.

[upload-artifact v7](https://github.com/actions/upload-artifact/releases/tag/v7.0.0) preserves zipped archives by default; the SBOM name, path and retention inputs still apply. The [cosign installer update](https://github.com/sigstore/cosign-installer/commit/398d4b0eeef1380460a10c8013a76f728fb906ac) stays on cosign v2, preserving the existing sign/attach/attest commands.

Workflow YAML parses successfully. The combined release workflow, ARM64 build, GitHub signing and artifact upload require a subsequent CI run; they have not been published or triggered as part of this preparation.

## Application verification

- Full workspace build and backend production bundle succeed.
- Backend: 224 tests pass, including real SMTP password-reset tests, collection auto-approval, season-scoped requests, grouped pagination/owner access, and idempotent release-note registration.
- Frontend: 109 tests pass, including grouping by media/requester, safe parsing of season scopes, numeric season label order (including season 10 and multi-season requests), and expanded-card positioning at viewport edges.
- Browser: grouped cards reserve 160px in the grid. The same frame extends over adjacent cards, with season/status labels wrapping side by side and no repeated header. Only one group expands at a time. Pointer entry/exit, keyboard opening, Escape, nested settings, season-specific approval, internal scrolling through 25 seasons, media links, visible download titles, and 320px viewport bounds were checked with fixture data.
- Linux AMD64 image built from the repository Dockerfile, using Node 22.23.2. An isolated container with a temporary empty database and no network starts successfully, serves the frontend, registers one bilingual 0.10.0 note, passes SQLite integrity checking and shuts down gracefully in under a second.
- Existing warnings remain: the large admin chunk and Vite's future native config-loader warning. No warning threshold was weakened.

## Data and upgrade behavior

No Prisma schema migration is added. The 0.10.0 note is upserted at boot after existing migrations. Before production restart, retain a verified SQLite backup and the previous image for rollback.

Grouping changes presentation and pagination; request IDs, users, season scopes, statuses and approval actions remain separate. Existing pending collection requests are not retroactively approved. The ordinary row-based request API remains available when `groupBy=mediaUser` is omitted.

## Data and upgrade behavior

The release now includes additive migrations for routing tags, request season numbering and
durable post-migration jobs. The metadata upgrade queues one full sync for existing enabled
Sonarr/Radarr libraries; completed work is not replayed on restart. See
[service metadata](../service-metadata.md) and [post-migration jobs](../post-migration-jobs.md).

`20261030230000_patchnote_0100` installs the final bilingual release notes through SQL. It
upserts only version 0.10.0, preserving its existing ID and all other releases. The development
startup seed is removed so it cannot overwrite the SQL content. This note-only migration
does not enqueue another sync or reset library data.

`20261030233000_patchnote_0100_date` aligns the 0.10.0 date with the historical ISO-text
storage format. SQLite sorts text ahead of integers in descending order, so the draft's
millisecond timestamp placed 0.10.0 below older releases and outside the 15-note API window.
The corrective migration preserves all earlier dates and migration checksums.

Before production restart, retain a verified SQLite backup and the previous image for rollback.
This content migration changes no schema and needs no database rollback to run the previous
image. The previous development image would reinsert its draft note at startup; redeploying
the new image after that requires reapplying this note's upsert and date correction, since Prisma has already
recorded the migration. Do not reset the database or delete migration history for this.

Grouping changes presentation and pagination; request IDs, users, season scopes, statuses and approval actions remain separate. Existing pending collection requests are not retroactively approved. The ordinary row-based request API remains available when `groupBy=mediaUser` is omitted.

## Audit corrections (2026-10-31)

- Incremental sync checks native TMDB ambiguity against the complete instance catalog,
  including entries outside the incremental batch. Exact TVDB matches remain valid.
- Request deduplication compares each request's own folder, service, profile, routed tag set
  and series type. Different variants remain requestable; equivalent labels still deduplicate.
- If routing metadata cannot be resolved, existing media can still receive pending requests.
  Only identical explicit quality options and folders deduplicate in that fallback.
- Stale season catalogs no longer display a complete/partial availability badge. Live requests
  and downloads retain their status; the dated-cache notice remains visible.
- Regression tests reproduced the failures before correction. The full suite passes:
  355 backend tests in 41 files and 173 frontend tests in 24 files. Production build passes
  with the existing large-chunk warning. Independent review found no additional defect.
- The real season component was checked in a browser with isolated fixture data: stale data
  displays "Non vérifiée"; switching to fresh complete data restores "Complète" and hides
  the quick-request button. No browser console error was observed.
- These corrections require no SQL migration, database reset or replay of the full-sync job.
